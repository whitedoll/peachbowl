# 브랜드 톤 학습 절차

기존에 올린 상품 페이지를 읽어 `references/brand-voice.md` 를 만들거나 갱신한다.
**상품 3~6개면 충분하다.** 잘 팔린 상품과 최근 상품을 섞어서 고른다.

## 0. smartstore.naver.com 은 브라우저로 접근이 막혀 있다

2026-08-19 확인: 인앱 브라우저 · 크롬 확장 · WebFetch **세 경로 모두**
`smartstore.naver.com` 을 도메인 정책으로 차단한다. 우회하지 말 것.

따라서 **로컬 파일 경로가 기본 방식**이다. 아래 3번(로컬 캡처 읽기)으로 바로 간다.
1~2번의 브라우저 방식은 정책이 풀렸거나 다른 도메인(자체몰 등)일 때만 쓴다.
브라우저를 시도했다가 차단되면 즉시 로컬 방식으로 전환하고 사용자에게 캡처를 요청한다.

## 1. 크롬 도구 로드

이 도구들은 지연 로딩이므로 한 번의 호출로 모두 가져온다.

```
ToolSearch  query:
select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__read_page
```

로그인된 세션이 필요 없는 공개 상품 페이지라면 인앱 브라우저(`mcp__Claude_Browser__*`)로도 된다.
판매자센터처럼 로그인이 필요한 화면은 반드시 크롬 확장 쪽을 쓴다.

## 2. 상품 페이지 수집

사용자가 스토어 URL 하나만 줬다면 그 스토어의 상품 목록에서 상위 상품 URL 을 뽑아
**어떤 상품을 분석할지 목록으로 보여주고 확인받은 뒤** 진행한다.

각 상품 페이지에서:

1. `navigate` → 상품 URL
2. `get_page_text` → 상품명, 옵션명, 요약 설명 등 **텍스트로 존재하는 카피** 확보
3. 상세 영역까지 스크롤 후 `computer{action:"screenshot"}`

> **중요:** 스마트스토어 상세페이지는 대부분 한 장의 긴 이미지라서 `get_page_text` 로는
> 카피가 안 나온다. 이 경우 상세 영역을 3~5회 스크롤하며 스크린샷을 찍고,
> 스크린샷 이미지를 직접 읽어서 카피를 옮겨 적는다. 텍스트가 안 잡힌다고 건너뛰지 않는다.

## 2-B. 로컬 캡처에서 읽기 (기본 방식)

사용자에게 아래를 요청한다.

> 크롬에서 상품 페이지를 연 뒤 상세 영역까지 **한 번 끝까지 스크롤**하고
> (이미지가 지연 로딩됩니다), 전체 페이지 캡처 확장으로 한 장을 저장하거나
> 상세 이미지들을 우클릭 → 이미지를 다른 이름으로 저장 해서
> `D:/peach/reference/<상품명>/` 폴더에 넣어주세요.

전체 페이지 캡처는 세로 3만~4만 px 이라 **Read 로 그냥 열면 축소돼서 글자를 못 읽는다.**
`scripts/read_capture.py` 로 구조를 훑고 필요한 구간만 원본 해상도로 잘라 읽는다.
(Pillow 필요: `python -m pip install Pillow`)

스크립트는 `D:/peach/reference/<상품ID>/` 안의 `*.png` 를 파일명 끝 번호 순서대로
세로로 이어붙인 뒤 처리한다. 캡처가 여러 장으로 쪼개져 있어도 그대로 두면 된다.

```bash
python scripts/read_capture.py sheet <상품ID> [<상품ID> ...]
```
전체 페이지를 세로 6000px 단위로 잘라 신문처럼 옆으로 늘어놓은 **축소 대지**를 만든다.
이걸 Read 로 한 장만 열면 페이지 전체 구조와 글자 블록 위치가 한눈에 보인다.

```bash
python scripts/read_capture.py prof <상품ID>
```
행별 밝기·검은픽셀 비율로 **글자가 있을 만한 y 구간**을 뽑아준다.
흰 배경 위 텍스트만 잡히므로, 사진 위 캡션이나 컬러 배경 위 글자는 대지로 직접 찾는다.

```bash
python scripts/read_capture.py crop <상품ID> <y0> <y1>
```
해당 구간을 잘라 가로 1400px 로 저장한다. **세로 1700px 이하로 끊어야** Read 에서
글자가 선명하다. 출력된 경로를 Read 로 연다.

읽으면서:

1. 이미지에 인쇄된 카피를 **원문 그대로** 옮겨 적는다 — 이게 톤 분석의 원재료다
2. 상품명·가격·옵션은 캡처 최상단 스마트스토어 UI 영역(보통 y 0~1700)에 있다
3. 강조색 hex 가 필요하면 크롭 구간에서 채도 높은 픽셀을 세어 뽑는다

## 3. 추출할 것

각 페이지마다 아래를 메모한다. 인상평이 아니라 **인용 가능한 근거**를 모은다.

### 문체
- 종결어미 분포: `~습니다` / `~해요` / `~합니다` / 명사형 종결 중 무엇이 주력인가
- 평균 문장 길이 (짧게 끊는가, 길게 잇는가)
- 호칭: 고객님 / 여러분 / 2인칭 없음
- 자기 지칭: 저희 / 우리 / 브랜드명 / 없음
- 느낌표·물결표·이모지·특수기호(◆ ▷ ★) 사용 빈도

### 어휘
- 반복해서 등장하는 단어와 표현 (그대로 목록화)
- 브랜드 고유 용어 (제품 라인 이름, 자체 등급 표기 등)
- 의도적으로 **쓰지 않는** 말 (예: 최저가, 대박, 강추)

### 구성
- 섹션 순서와 이름 (예: 인트로 → 소재 → 착용컷 → 사이즈 → 배송)
- 소구점을 몇 개 쓰는가
- 표를 쓰는가, 문장으로 푸는가
- 후기·상세컷·연출컷의 비중

### 시각
- 배경색, 강조색 (스크린샷에서 눈으로 판단해 hex 근사값으로 기록)
- 여백 감각: 빽빽한가 여유로운가
- 사진 톤: 밝고 화사 / 차분하고 어두움 / 무채색
- 제목 글자 크기 대비 본문 크기

### 실제 문장 3~5개
가장 그 브랜드다운 문장을 **원문 그대로** 옮겨 적는다. 이게 나중에 가장 유용하다.

## 4. brand-voice.md 작성

`references/brand-voice.md` 를 아래 형식으로 덮어쓴다.
추상적인 형용사("감성적임")로 끝내지 말고, **다음에 문장을 쓸 때 바로 따라할 수 있는
구체적 규칙**으로 적는다.

```markdown
# 브랜드 톤  ({{브랜드명}})

분석한 상품: {{URL 목록}}
분석일: {{YYYY-MM-DD}}

## 문체 규칙
- 종결어미는 `~습니다` 로 통일한다. (분석 6개 중 6개)
- 한 문장 25~35자. 두 문장 이상 이어붙이지 않는다.
- 고객을 "고객님"으로 부르지 않는다. 2인칭을 쓰지 않는다.
- 느낌표는 페이지당 0~1개.

## 즐겨 쓰는 표현
- "매일 손이 가는", "부담 없이", "오래 두고" ...

## 쓰지 않는 표현
- ...

## 구성
- 소구점 3개 고정, 각 소구점 아래 연출컷 1장
- 사이즈는 항상 표로, 오차 문구 병기

## 색·여백
- 배경 #FFFFFF, 섹션 배경 #F5F2EE, 강조 #2B2B2B
- 섹션 상하 여백 넉넉하게 (80px 이상)

## 참고 원문
> "{{실제 문장 1}}"
> "{{실제 문장 2}}"
```

## 5. 이후

`brand-voice.md` 가 존재하면 매 상세페이지 생성 시 이 파일이
`copywriting.md` 의 기본 톤보다 **우선한다**. 단, `compliance.md` 의 금지 표현은
브랜드 톤보다 우선한다 — 기존 페이지에 금지 표현이 있었더라도 따라 쓰지 않고,
사용자에게 "기존 페이지의 이 표현은 규정상 위험하다"고 알린다.
