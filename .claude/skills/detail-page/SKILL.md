# 상품 상세페이지 생성

상품 이미지 + 간단한 설명 → 스마트스토어에 올릴 수 있는 단일 HTML 상세페이지.

## 핵심 원칙

1. **사진에 없는 사실을 지어내지 않는다.** 원산지, 성분, 함량, 인증, 제조사, 용량, 소재 혼용률은
   사용자가 알려준 것만 쓴다. 모르면 `※ 확인 필요` 로 남기고 넘어간다 — 추측해서 채우면 허위광고가 된다.
2. **표현은 법을 먼저 통과한다.** 카피를 쓰기 전 `references/compliance.md` 를 반드시 읽는다.
3. **사진을 실제로 본다.** 파일 경로만 받고 넘어가지 말고 Read 도구로 이미지를 직접 열어
   색감·재질·구도·조명 톤을 확인한 뒤 카피를 쓴다.
4. **어조는 지어내지 않고 학습한다.** `references/brand-voice.md` 에 학습된 톤이 있으면
   그것을 따른다. 없으면 사용자에게 기존 상품 페이지 URL 을 받아 학습할 수 있다고 알린다.

## 두 가지 모드

| 사용자가 말한 것 | 실행할 것 |
|---|---|
| 기존 상품 페이지 URL 을 주며 "톤 학습", "이 느낌으로" | **학습 모드** → `references/learn-brand-voice.md` 절차 실행 후 `references/brand-voice.md` 갱신. 그다음 생성 모드로 이어간다 |
| 사진 + 설명을 주며 상세페이지 요청 | **생성 모드** → 아래 작업 순서 |

## 작업 순서 (생성 모드)

### 0단계 — 브랜드 톤 로드

`references/brand-voice.md` (문체·카피) 와 `references/visual-style.md` (촬영·연출·레이아웃)
를 읽는다. 사진을 고르고 배치할 때는 `visual-style.md` 가 기준이다.

- **학습된 내용이 있으면** 그 규칙이 `references/copywriting.md` 의 기본 톤보다 우선한다.
  종결어미, 문장 길이, 호칭, 즐겨 쓰는 표현, 섹션 구성, 색상을 그대로 따른다.
- **아직 학습 전이면** 기본 톤으로 진행하되, 결과 보고 시 학습을 한 번 권한다.
- 어느 경우든 `references/compliance.md` 의 금지 표현이 브랜드 톤보다 위에 있다.

### 1단계 — 입력 수집

사용자가 준 것을 정리한다.

- 이미지 파일 경로 목록 (없으면 폴더에서 `*.jpg *.png *.webp` 를 찾아 후보를 보여주고 확인받는다)
- 상품명 / 한 줄 설명 / 가격 / 옵션 or 사이즈
- 브랜드명, 톤 (예: 미니멀, 감성, 실용, 프리미엄)

### 2단계 — 이미지 관찰

**사진을 한 장씩 Read 로 열지 않는다.** 20~30장이면 그것만으로 컨텍스트가 다 찬다.
색인 대지를 만들어 한 장으로 훑고, 애매한 것만 개별로 연다.

```bash
python scripts/prep_images.py grid <사진폴더>
```

격자 칸마다 번호가 찍힌 대지가 나온다. 이걸 Read 로 한 번 열면 전체를 분류할 수 있다.
분류가 끝나면 역할 이름을 붙여 배치한다 (가로 860px 로 리사이즈되어 저장된다).

```bash
python scripts/prep_images.py place <사진폴더> output/<슬러그>/img \
  key=1 point1=12 model-g1=2 detail1=17 ...
```

`미사용:` 로 출력된 번호가 있으면 의도한 것인지 확인한다. 좋은 컷을 빠뜨리기 쉽다.

대지에서 아래를 읽어 메모한다. 이 메모가 카피의 재료다.

- 무엇이 찍혀 있는가 (제품 단독컷 / 연출컷 / 디테일컷 / 착용컷 / 사이즈 비교컷)
- 색상, 재질감, 마감, 형태
- 배경과 조명 톤 → 페이지 배경색과 강조색을 여기서 뽑는다

그다음 이미지를 역할별로 배정한다:

| 역할 | 쓰임 |
|---|---|
| KEY | 최상단 히어로 컷. 가장 잘 나온 연출컷 |
| POINT 1~3 | 소구점 3개에 각각 붙일 근거 컷 |
| DETAIL | 재질·마감 클로즈업 |
| SIZE | 사이즈/구성 안내 컷 (없으면 섹션 생략) |

### 3단계 — 빠진 필수 정보 확인

`references/compliance.md` 의 상품정보제공고시 항목 중 **해당 품목에서 빠진 것만** 모아
한 번에 질문한다. 하나씩 여러 번 묻지 않는다. 사용자가 "모르겠다/나중에"라고 하면
해당 칸을 `※ 판매자 확인 필요` 로 두고 계속 진행한다.

### 4단계 — 카피 작성

`references/copywriting.md` 의 섹션별 작법을 따르되, 0단계에서 읽은
`references/brand-voice.md` 의 규칙으로 덮어쓴다. 우선순위는 다음과 같다.

```
compliance.md (금지 표현)  >  brand-voice.md (브랜드 톤)  >  copywriting.md (기본 작법)
```

작성 후 `compliance.md` 의 금지 표현 목록으로 자기 검열을 한 번 돌린다.

### 5단계 — HTML 생성

`assets/template.html` 을 복사해 채운다.

- 출력 위치: 작업 폴더의 `output/<상품명-슬러그>/index.html`
- 이미지는 같은 폴더의 `img/` 에 복사하고 **상대 경로**로 참조한다 (`./img/key.jpg`)
- `assets/img/` 의 회색 자리표시 이미지는 템플릿 미리보기용이다. **복사하지 않는다.**
- 강조는 `<em>` 하나로 통일한다. 색은 `:root` 의 `--accent` 한 줄로 바뀐다
- 카피는 `<br>` 로 8~18자씩 끊어 세로로 쌓는다 (`.copy` 블록)
- 템플릿의 `<!-- OPTIONAL -->` 로 표시된 섹션은 재료가 없으면 통째로 지운다.
  빈 섹션을 자리표시자로 남기지 않는다.
- 인라인 `<style>` 외의 외부 CSS·폰트·스크립트는 절대 추가하지 않는다.

### 5-B단계 — 이미지 내장 (필수)

```bash
python scripts/embed_images.py output/<슬러그>/index.html output/<슬러그>/standalone.html
```

**상대경로 버전만 만들고 끝내지 않는다.** 미리보기 창·채팅 전달·다른 PC 어디서든
HTML 은 `data:` URL 로 렌더링되는 경우가 많고, 그때 `./img/x.jpg` 는 기준 폴더가 없어
전부 깨진 이미지로 나온다. 파일 탐색기에서 직접 열 때만 보인다.

- `index.html` — 상대경로. 수정하기 쉬운 작업본
- `standalone.html` — 이미지 내장. 전달·미리보기·캡처용

이미지를 바꾼 뒤에는 `standalone.html` 을 다시 생성한다.
사용자에게 파일을 보낼 때는 **항상 `standalone.html` 쪽**을 보낸다.

### 6단계 — 미리보기

**`file://` 로 열지 않는다.** 미리보기 창은 `file://` 을 `data:` URL 스냅샷으로 바꿔
띄우기 때문에 상대경로가 깨지고, 같은 경로로 다시 navigate 해도 **예전 스냅샷을
그대로 붙들고 새 파일을 안 읽는다** (`force:true` 로도 안 된다).

로컬 HTTP 서버로 연다. 이게 유일하게 신뢰할 수 있는 방법이다.

```bash
python -m http.server 8765 --bind 127.0.0.1     # output/ 에서 실행, 백그라운드
```
```
mcp__Claude_Browser__preview_start { url: "http://127.0.0.1:8765/<슬러그>/standalone.html" }
mcp__Claude_Browser__computer      { action: "screenshot" }
```

이미지가 안 보이면 추측하지 말고 이 순서로 확인한다.

1. `document.documentElement.outerHTML.length` — 실제 파일 크기와 다르면 **스냅샷이 낡은 것**
2. `document.images[0].getAttribute('src')` — `./img/` 로 나오면 standalone 이 아니라 작업본을 보고 있는 것
3. `document.baseURI` — `data:` 로 시작하면 상대경로는 원래 해석되지 않는다
4. 위가 다 정상인데 `naturalWidth === 0` 이면 그때부터 파일을 의심한다

자리표시 이미지를 만들 때 한글을 쓰려면 PIL 기본 폰트로는 깨진다.
`C:\Windows\Fonts\malgun.ttf` 를 `ImageFont.truetype` 으로 지정한다.

```
mcp__Claude_Browser__preview_start  { url: "file:///D:/peach/output/<슬러그>/index.html" }
mcp__Claude_Browser__computer       { action: "screenshot" }
```

깨진 이미지, 넘치는 텍스트, 잘린 표가 없는지 눈으로 확인한 뒤 사용자에게 결과를 알린다.

## 스마트스토어 업로드 안내 (결과 보고 시 같이 전달)

스마트에디터 ONE 은 외부 CSS/스크립트를 걸러내므로, 이 HTML 을 그대로 붙여넣으면
레이아웃이 깨질 수 있다. 실무에서 안전한 순서:

1. 브라우저에서 HTML 을 열고 **가로 폭 860px** 로 맞춘다
2. 전체 페이지를 하나의 긴 이미지로 캡처한다 (세로 길이는 제한 없음, 파일당 10MB 이하)
3. 스마트에디터 ONE → 사진 → 그 이미지를 업로드
4. 상품 주요정보 / 상품정보제공고시는 HTML 이 아니라 **스마트스토어 입력폼에 따로** 넣는다

HTML 소스를 직접 쓰고 싶다면 에디터의 `HTML` 모드에 붙여넣되, 업로드 후 PC·모바일
미리보기를 둘 다 확인하라고 안내한다.
